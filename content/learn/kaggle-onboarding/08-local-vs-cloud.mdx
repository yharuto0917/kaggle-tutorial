## 3 つの実行環境

| 環境                | 長所                                             | 注意点                         |
| ------------------- | ------------------------------------------------ | ------------------------------ |
| **Kaggle Notebook** | セットアップ不要・コンペデータ直結・無料 GPU/TPU | クォータ・セッション時間に上限 |
| **Google Colab**    | 無料/有料 GPU・Google Drive 連携                 | Kaggle データは API 連携が必要 |
| **ローカル**        | 環境を自由に構築・時間制限なし                   | GPU は自前・初期構築の手間     |

## おすすめの進め方

- **入門〜中級**：まずは **Kaggle Notebook** だけで完結させるのが最速。本コースのコード例も
  そのまま Kaggle / Colab で開いて実行できます。
- **本格的に取り組む**：ローカル（または Colab）でコードを管理しつつ、学習は GPU 環境で回す
  ハイブリッドが定番です。

<Callout type="tip">
	環境を増やすほど「動かない」原因が増えます。最初は 1 つの環境に絞り、 ワークフロー（データ取得 →
	学習 → 提出）を体に覚えさせましょう。
</Callout>

## 再現性を意識する

どの環境でも、**乱数シードの固定**と**実行の記録（バージョン保存）**を習慣にすると、
スコアの変動要因を切り分けやすくなり、[[過学習]]や[[データリーク]]にも気づきやすくなります。
